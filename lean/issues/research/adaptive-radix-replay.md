# radix 分割数の途中変更を許す集約

## 証明済みの命題

メモリ圧迫で radix 幅を増やし一部の入力を再生しても、グループごとの nullable 状態と多重度を保存する。

## モデルと適用条件

封印済みバケット、書込み中の spill、再試行の世代・所有権を明示する。

## 回帰例

親バケットを一部マージした後に親全体を子で再生すると先頭部分だけ二重加算される。

## 完了条件

任意の分割履歴・予算で逐次結果に一致し、同一出現が消費される回数を証明する。

実装との照合先は [executor/detail/pipeline/ooc_group_agg_sink.cpp](../../../executor/detail/pipeline/ooc_group_agg_sink.cpp)。

## 差し戻し後の提出型

[RadixReplayOwnership.Goal](../../TinylambOpt/ResearchGoals/RadixReplayOwnership.lean) は、一回消費を仮定せず、入力の出現 ID が一意であることだけを前提にする。任意の命令列の途中で、消費済み ID と全バケットの保留 ID を合わせた多重集合が元入力に等しいこと、所有トークンと radix prefix が正しいこと、最終 drain 後の消費回数とグループ集約結果を要求する。旧提出物の集約評価器を再利用する。

このモデルでは drain は指定行数までを原子的に確定する。部分消費後の再分割は残りだけを子に移し、古いトークンへの再送は無効になる。実ファイルへの部分書込みやクラッシュ復旧の遷移を扱う場合は、どの時点で所有権が移るかの追加仕様が要る。一般命題は未証明。
