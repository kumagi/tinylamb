# ClickHouse との保存サイズ差から調べた圧縮・実行の12題

## どのベンチマークで差が出たか

保存されている3エンジン比較用 fixture を、2026-11-26 にファイル長から再集計した。各ワークロードで、tinylamb の全 TLCS ヘッダと ClickHouse の全対象 part の行数・テーブル数を照合した。最後の列は同じ tinylamb ファイルに以前の独立1 MiBフレーム試作を適用した全量実測値。[以前の試作と測定条件](compression.md)

| 保存済み fixture | 行数 | tinylamb（B） | ClickHouse（B） | tinylamb / ClickHouse | 1 MiB試作（B） |
|---|---:|---:|---:|---:|---:|
| ClickBench | 99,997,497 | 59,421,543,500 | 9,410,847,370 | 6.31 | 10,114,664,031 |
| TPC-H SF10 | 86,586,082 | 6,697,242,348 | 2,656,602,703 | 2.52 | 2,598,364,046 |
| TPC-DS SF10 | 191,496,658 | 10,319,679,752 | 3,658,807,249 | 2.82 | 3,298,867,451 |

tinylamb は各 fixture の DB 本体・列ファイル・ブロックファイル、ClickHouse はユーザーテーブルの非重複 part 内の全ファイル（データ、マーク、索引、part メタデータを含む）を数えた。WAL、サーバーログ、システム表、ファイルシステムのブロック丸めは集計外。これは保存当時の fixture の値。現在の writer には、6バイトの時刻、辞書、Zstd ラッパーなどの選択肢がある。[現在の列形式と writer](../../../table/tlcs_file.cpp#L1346)

**ClickBench では、50.01 GB の差のうち 27.25 GB（54.5%）が4本の文字列列に集中した。** 同じ fixture に対する1 MiB試作と ClickHouse の残差は 703,816,661 B。汎用のフレーム圧縮だけでも元の差の大半を埋められた。どの改善がこの残差を埋めるかは別に測る必要がある。

| ClickBench の列 | tinylamb の本体・終点等（B） | ClickHouse の当該列の全ストリーム・マーク（B） |
|---|---:|---:|
| Title | 9,887,370,969 | 1,212,874,607 |
| URL | 9,438,827,995 | 1,475,544,429 |
| Referer | 7,062,448,414 | 1,377,642,327 |
| OriginalURL | 5,717,463,100 | 788,116,154 |
| EventTime | 2,599,934,922 | 266,382,118 |
| ClientEventTime | 2,599,934,922 | 267,958,494 |
| LocalEventTime | 2,599,934,922 | 266,488,581 |

ClickHouse の保存済み DDL は `MergeTree ORDER BY (CounterID, EventDate, UserID, EventTime, WatchID)`、2個の part の既定コーデックはともに `ZSTD(3)`。文字列には本文とサイズのサブストリームがあり、時刻は `DateTime` 型。tinylamb のこの fixture は時刻を22バイトの文字列と行ごとの終点で持つ。列別サイズは差の**場所**を特定する。型、行順、コーデックそれぞれの寄与は合計サイズから逆算できない。[ClickHouse の圧縮ガイド](https://clickhouse.com/docs/data-compression/compression-in-clickhouse)

## 同じ98,304行で何が変わったか

元の `hits.tsv` をファイル長で12等分し、各位置以後の完全な8,192行を採った。文字列は fixture の16進表記を元バイトに戻した。以下は Zstandard 1.5.7、レベル3、区間・列ごとに独立したフレームでの計測。標本内の全行を復元して照合した。全表への外挿やクエリ時間の計測はしていない。[測定スクリプト](fixtures/clickbench_layout.py)

- **行順**　12区間すべてで ClickHouse の5列キーによる安定ソートが恒等置換になった。4本文字列の圧縮後サイズもバイト単位で同じだった。この標本では再ソートに削減効果がない。各区間の元行番号を機械的に16ビット値＋Zstd で保存すると、それだけで合計178,620 B増える。
- **長さと本文の分離**　`(ULEB長, 本文)` を一緒に圧縮した場合と、2ストリームに分けて追加の4 B位置情報を課金した場合を比較した。`URL` は 1,502,041 → 1,496,230 B、`OriginalURL` は 644,871 → 643,351 B。逆に `Title` は 1,248,213 → 1,310,621 B、`Referer` は 1,267,523 → 1,271,153 B。分離採用の判断には、Q28 で本文を読まずに済む価値も入る。
- **URL の行内参照**　`OriginalURL` は84,166行が空で、非空かつ同じ行の `URL` と一致するものは0行だった。「空・URLをコピー・リテラル」のタグ形式は 644,871 → 647,750 B と増えた。一方、区間別 URL 辞書の各値に最頻の `URLHash` を対応づけると、辞書エントリ延べ39,018に加えて4,540行の例外が必要だった。辞書本体・例外 ID の費用と Q41 のハッシュ単独アクセスが採用判断に残る。
- **時刻の列間差分**　各値を符号付き64ビットの UTC 秒に変換し、元の22バイト表記を復元できることを確認した。3列独立で 586,911 B、`EventTime` を基準にほかの2列を秒差にすると 546,628 B（いずれもフレーム本体合計）。参照元を各区間で選び、循環する参照を除くと、参照元タグ込みで 540,705 B。現在の `TemporalText` の6バイト表現と10 Bのラッパーを再現した同じ標本では 640,871 B。候補にも同じラッパー長を36回課金すると **541,065 B、15.6%減**だった。この比較は3列のペイロードで、DB全体のサイズは対象外。単独投影では残差を展開するための別フレーム読取りが発生し得る。[時刻のパック形式](../../../table/tlcs_compression.cpp#L418)

## 未証明の命題

各行を独立した `Goal : Prop` として登録した。実装の判断単位で数え、具体例を試す `#guard` は件数に含めていない。

| 保存形式の命題 | 証明・反証で決めたいこと |
|---|---|
| `ClockForest` | 実測した方向別の圧縮費用から、各時刻を独立に保存するか別列との差分にするかを選ぶ。部分集合 DP が復号可能な最小バイトの参照関係を返すか。 |
| `ClockWindow` | 時計の秒差を固定幅の窓と例外表に分ける。基準値自身の可変長費用を含めても、ゼロと各観測値の窓端だけ調べれば最適な基準値を選べるか。 |
| `RunSidecar` | 再クラスタリング後の元行 ID を、昇順 run のラベル1列だけで復元できるか。恒等順序は1 run で済み、必要な連続 run 数も最小になるか。 |
| `TieOrientation` | クラスタキーが同順位の群ごとに前向き・逆向きを選べるとき、接頭辞辞書の群境界を含む実バイト長を2状態 DP で最小化できるか。元行順の復元費用は別に課金する。 |
| `DictionaryAdmission` | 共有辞書の保存費に加え、クエリが辞書を初めて読む費用を入れて採用 frame を選ぶ。読取集合が入れ子か互いに素の場合、木上の DP が達成可能な最大削減を返すか。 |
| `HashExceptions` | URL 辞書の各エントリに最頻ハッシュを付け、異なる値だけ行 ID で補正する。固定長例外の件数を最小化し、ハッシュ衝突を含めて述語に通る元行を復元できるか。 |

| 実行時の命題 | 証明・反証で決めたいこと |
|---|---|
| `ClockRange` | 基準時刻と秒差の上下界だけで範囲述語を決められる必要十分条件を求める。NULL と絶対時刻で保存した例外を扱い、境界をまたぐ行だけ残差を読む。 |

| `AnchorDemand` | 参照・リテラル混在列で、任意の順序・重複の gather に答えるために必要な基準フレームの最小集合を、値の復号前に決められるか。 |

| `DefaultGroups` | 多列の既定値と疎な例外で、`GROUP BY` の各組の重複度を例外行だけから求める。複数列に現れた同じ行、すべて既定値の行、NULL とゼロを区別する。 |

[実行の Lean 定義](../../TinylambOpt/ResearchGoals/ClickBenchLayout/Execution.lean)

実装の接続先は TLCS のブロック writer、列の選択読取り、辞書・文字列用の集約経路。時刻を数値にするには元の綴りを復元できる書式、列参照には同じ世代・同じ行対応が必要になる。残差モデルの整数は Lean の `Int` であり、機械整数での差分は範囲チェックが必要。[TLCS 読取り](../../../table/tlcs_file.cpp)・[列実行経路](../../../executor/detail/columnar_tlcs_fast_path.cpp)
