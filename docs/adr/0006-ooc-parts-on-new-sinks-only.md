# Out-of-Core の部品は新しいシンクからだけ使う

Status: accepted（2026-11-16 決定、2026-11-17 P2/P3a/P3b 実装済み: `executor/detail/ooc/`, `executor/detail/pipeline/`, `executor/pipeline_lowering.*`；`TINYLAMB_EXEC_ENGINE` の既定も `pipeline` 化済み）
決定者: ユーザー
関連: [`ooca-v2.md`](../../ooca-v2.md) §4 D4、[`TODO.md`](../../TODO.md) S2 / S5 / S6 / S7 / S10、
[ADR 0002](0002-wasm-fused-execution.md)

## 背景

元の out-of-core 設計（`ooca-v2.md`）は、旧 `ExecutorBase` 木の演算子を 10 種以上書き直して
メモリを入力に依存させない形にする計画だった。一方 `TODO.md` は、Executor を
「パイプライン IR ＋ シンク契約」に置き換え、S10 で旧演算子と手書き融合形を削除する。
両方を進めると同じ演算子を 2 回書くことになる。

## 決定

1. 外部ソート、再帰分割、スピル可能ストアは、演算子に依存しない部品として作る
   （`executor/detail/ooc/`）。
2. 部品のインターフェースは `TODO.md` S2 のシンク契約
   （ワーカー別の `Sink` → `Combine` → `Finalize`）とソースに合わせる。
3. 新しいシンク（`SortSink`、`HashBuildSink`、`GroupAggSink`、`WindowSink` など）は、
   最初からこの部品の上に作る。入力を全て溜める実装を先に作って後から直すことはしない。
4. **旧演算子・`Relation`・`SpillFile`・手書き融合形には原則として手を入れない（P2/P3a/P3b の実装で一部移行済み）。**
   出力を `rows_` / `output_` に溜め直す問題も、旧演算子では直さない。
5. 規模のゲートは `TINYLAMB_EXEC_ENGINE=pipeline` で、`legacy_source_ms` が 0 のクエリだけを
   対象にする。対象になったクエリの割合を毎回記録する。

## 帰結

- 本計画の演算子部分は `TODO.md` の S2（WASM を含まない）が前提になる。
  WASM を使うかどうか（ADR 0002）には依存しない。Tier 0 のシンクがあれば足りる。
- `LegacySource` に包まれた部分木は、置き換わるまでメモリが入力に比例したまま残る。
  ClickBench や TPC-DS の RSS が下がり始めるのは、S5 のシンクが入ってからになる。
- 旧演算子のための許可リスト（強制予約、`Collect()`、`ReadAllRows()` の呼び出し）は、
  旧演算子の削除と一緒に消える。新しいコードからの呼び出しは lint で禁止する。
- 置き換えの順番は、どの旧演算子がどれだけメモリを溜めているかの実測の大きい順にする。

## 検討した案

| 案 | 採否 |
|---|---|
| 旧演算子を全て書き直す（元文書） | 不採用。S10 で消えるコードへの投資になる |
| 部品を旧演算子と新シンクの両方から使う | 不採用。旧演算子側の接続コードも S10 で消える |
| 旧演算子の「出力の溜め直し」だけ先に直す | 不採用。効果は大きいが、同じく消えるコードであり、新シンクの実装を優先する |

## 見直す条件

S2 の着手が大きく遅れ、その間に旧経路のメモリ消費が実用上の障害になった場合は、
3 番目の案（出力の溜め直しだけ直す）を再検討する。
