# 常駐ページはバイト数で数え、固定長フレームにしない

Status: accepted（2026-11-16、方針のみ）
決定者: ユーザーの委任による Claude の判断
関連: [`ooca-v2.md`](../../ooca-v2.md) §4 D8、[ADR 0009](0009-page-directory-in-stages.md)

## 背景

元の設計（`ooca.md`）は「固定長フレームの配列 `Frame[0..F-1]` ＋ Clock / 2Q / S3-FIFO」を
提案した。現行のコードはそれと形が違う。

- メモリ上の `RowPage` は 32 KiB の固定イメージではない。編集中の状態（`live_packed_`）と
  コミット済みの状態（`committed_packed_`）を別々に持つ可変長の構造である。
- 常駐量は既にバイト数で数えている（`resident_bytes_`、`Page::accounted_bytes_`）。
- 退避は FIFO ＋参照ビットで動いている（`eviction_fifo_` と `Page::TakeReferenced()`）。
- 扱う単位の大きさが揃っていない（ページ 32 KiB、TLCS のブロック、LSM のランのブロック）。
- `s3-fifo.md`（削除済み）は、既に無いファイル（`page/page_pool.cpp`、
  `common/vm_cache_impl.cpp`、`index/lsm_detail/cache.hpp`）を前提にした別方向の計画
  （mmap の安定アドレス空間）である。

メモリを入力量に依存させないために必要なのは、非常駐ページのメモリを 0 に近づけることであり、
常駐ページを固定長にすることではない。

## 決定

1. 固定長フレームの配列は作らない。常駐オブジェクトは可変長のまま、バイト数で数える。
2. 要件は「非常駐ページが RAM に残すものを最小にする」こと（ADR 0009）。
3. 退避方式は現行の FIFO ＋参照ビットのまま始める。置き換えるのは、DB が RAM を超える
   規模で方式の差が測れてからにする。
4. `s3-fifo.md` は本 ADR と `ooca-v2.md` が置き換える。

## 検討した案

| 案 | 採否 |
|---|---|
| 固定長フレーム配列（元文書） | 不採用。メモリ上のページ表現を作り直すことになり、目的に対して過大 |
| mmap の安定アドレス空間（`s3-fifo.md`） | 不採用。前提のコードが既に無く、可変長の `RowPage` と合わない |
| 退避方式を先に S3-FIFO へ替える | 見送り。現状のベンチマークは RAM に収まり、方式の差が測れない |

## 見直す条件

メモリ上のページ表現を固定イメージに変える別の理由（ゼロコピーのスキャン、`O_DIRECT`）が
出てきたとき。そのときは固定長フレームを改めて検討する。
