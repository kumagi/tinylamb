# 結合

結合は二つの入力から、条件を満たす行対または条件の存在情報を作る。物理方式が異なっても、結合種別、`NULL`、重複、残余条件の意味を一致させる必要がある。

## 1. 結合種別

以下では、左入力を探索側（probe）または外側（outer）、右入力を構築側（build）または内側（inner）と呼ぶ。結合種別ごとの出力は次のとおりである。

| 種別 | 一致時 | 不一致時 | `NULL` キー |
|---|---|---|---|
| 内部結合（Inner） | 全一致対 `left + right` | 何も出さない | 通常は一致しない |
| 左外部結合（Left Outer） | 全一致対 | `left + NULL-right` | 左行を補完して保存 |
| 右外部結合（Right Outer） | 全一致対 | `NULL-left + right` | 右行を補完して保存 |
| 完全外部結合（Full Outer） | 全一致対 | 両側の不一致行を補完 | 各側を保存 |
| 準結合（Semi） | 左行を 1 回 | 何も出さない | 一致しない |
| 反結合（Anti） | 何も出さない | 左行を 1 回 | 「一致なし」なので左行を出す |
| NULL 対応反結合（Null-aware Anti） | 何も出さない | 三値 `NOT IN` に従う | `UNKNOWN` として通常は出さない |
| マーク結合（Mark） | `left + TRUE` | `left + FALSE/NULL` | 構築側の `NULL` の有無で `FALSE` または `NULL` |
| 単一結合（Single） | 唯一の `left + right` | `left + NULL-right` | 一致しない。複数一致は失敗 |

通常の複合等値キーでは、どれか一要素が `NULL` なら比較結果は `UNKNOWN` であり一致しない。`IS NOT DISTINCT FROM` に由来する NULL 安全なキーだけは、`NULL` を比較可能な専用タグへ符号化し、`NULL` 同士を一致させる。

### 1.1 通常の反結合と NULL 対応反結合

通常の反結合は `NOT EXISTS` の物理化に対応する。左キーが `NULL` でも右に一致行はないので左行を返す。

NULL 対応反結合は `x NOT IN (S)` の三値論理を直接表す。

- `S` が空なら、`x` が `NULL` でも全左行を返す。
- `S` に `NULL` が一つでもあれば、非一致の結果は `UNKNOWN` なので結果は空になる。
- `S` が非空かつ `NULL` を含まないとき、左キー `NULL` は `UNKNOWN` なので返さない。
- 非 `NULL` 左キーは、右に一致がないときだけ返す。

### 1.2 残余述語

等値キーで候補対を求めた後に、非等値条件を評価することがある。この条件を残余述語（residual predicate）と呼ぶ。外部結合では、キーが等しくても残余述語を満たす相手がなければ、その行を不一致行として `NULL` で補完する。

内部結合の残余述語と結合述語には、`WHERE` と同じ許容的な AND 評価を使える。準結合、反結合、外部結合では、式エラーを単なる不一致として扱うと出力が変わるため、エラーを親へ伝える。

## 2. `CrossJoin`

`CrossJoin` は右入力をメモリへ全件保持し、各左行について右行列を先頭から走査して `left + right` を返す。条件は評価しない。

右入力が空なら出力も空であり、左入力を読む必要はない。右入力に `R` 行、左入力に `L` 行あると、出力は必ず `L × R` 行、時間も `Ω(LR)`、保持メモリは `O(R)` である。

右側を実体化した後は行を一つずつ返すが、最初の行を返す前に右側をすべて読む。合成した行には一意の物理位置を定められないため、位置を返さない。

右入力の失敗は状態に記録するものの、失敗前に右行を取得していれば、その行を使った部分的な直積を返すことがある。この場合も状態は失敗のままである。左入力が停止した理由は自身の状態へ転送しない。

## 3. `NestedLoopJoin`

`NestedLoopJoin` は右入力を全件保持し、左入力を既定 1024 行のブロックで読み、各右行と各左行の全候補対へ述語を評価する。計算量は一般に `O(LR × 述語費用)` で、索引も等値キーも必要としない。

対応する種別は、内部結合、左外部結合、準結合、反結合、マーク結合、単一結合である。

- 内部結合と左外部結合は、一致した全行対を作る。
- 左外部結合は、一致数 0 の左行へ右幅の `NULL` を付ける。
- 準結合は、一致数が 1 以上の左行を一度返す。
- 反結合は、一致数 0 の左行を返す。
- マーク結合は、左行へ真偽値の印を付ける。この入れ子ループ実装が返す印は、`TRUE` と `FALSE` の二値である。
- 単一結合は、一致を一つだけ保持し、0 件なら右を `NULL` 補完し、2 件目で失敗する。

準結合には、右側の一致が一意であることを検査する指定を付けられる。同じ左行に複数の一致が見つかると、そこで失敗する。

右入力と全出力をメモリに保持するため、処理の途中では行を返さない完全なブロッキング方式である。一致行と、左側を保存する結合の出力には、左の `RowPosition` を付ける。

## 4. `BatchNestedLoopJoin`

`BatchNestedLoopJoin` も右側を保持し、左側をブロック単位で全比較する。ブロック幅が 16 行未満に指定された場合は 16 行に引き上げる。`NestedLoopJoin` と異なり、明示的なパイプラインブレーカーとして扱い、完成した出力の推定バイト数を作業メモリへ計上する。

対応する種別は、内部結合、左外部結合、右外部結合、完全外部結合、準結合、反結合である。マーク結合、単一結合、NULL 対応反結合はこの実装の対象外である。

右外部結合と完全外部結合では、右行ごとの一致済みビットマップを、すべての左ブロックの処理が終わるまで保持する。全左行を処理した後、未一致の右行に左側の列数だけ `NULL` を付けて出力する。

一致行と左保存行は左位置を、未一致の右保存行は右位置を持つ。二つの物理行からなる一致行に付く位置は、更新対象として使うなら保存側の契約を別途確認する必要がある。

述語の評価に失敗すると、最初のエラーを状態に保存し、完成した出力を返す前に停止する。一方、左右の子が `false` を返した理由は確認せず、子の状態も転送しない。そのため、この演算子の状態だけでは、入力側で起きた失敗を判別できない。

## 5. `IndexJoin`

`IndexJoin` は左行を一つ取り、抽出した左キーで右表の索引に等値範囲を開く。右候補を順に読み、左・右から抽出した複合キー全体が同じ場合だけ `left + right` を返す。

索引の範囲開始・終了には抽出キーの先頭値を使い、完全な複合一致は候補行上で再検査する。したがって、右索引の先頭キーが左の先頭結合キーに対応していることが入力契約になる。

左 1 行当たりの探索量は `O(log R + 一致数)` と見積もれる。左入力が小さく、右索引で候補を十分に絞れる場合に適する。左入力が大きい場合は、索引探索の繰り返しとヒープへのランダムアクセスに時間がかかる。

内部等値結合（inner equi join）専用であり、外部結合の `NULL` 補完、準結合、反結合は行わない。合成した出力には物理行位置を返さない。現在の左行に候補がなければ、候補のある次の左行まで進む。

左入力の状態は転送しない。また、この演算子から索引反復子の状態を取得する手段もない。この境界から見ると、`false` は常に入力の末尾を表す。そのため、下位の障害を親まで完全に伝えることはできない。

## 6. `HashJoin`

`HashJoin` は、等値キーをハッシュ化する。一方の入力からハッシュ索引を作り、もう一方の入力の各行で索引を探索する。期待計算量は `O(L + R + 出力)` であり、入力順序は保証しない。

### 6.1 キー表現とハッシュ表

単一の対応可能な整数キーには、値オブジェクトへ箱詰めしない 64 ビット整数専用の高速処理を使う。複合キーや一般型は、型と値の境界を保った memcomparable バイト列へ符号化する。この形式では、バイト列の比較順と値の比較順が一致する。

ハッシュ索引には、オープンアドレス法と線形探索法を使い、負荷率を 0.7 以下に保つ。同じキーを持つ複数の行は、項目から連なるリストに保存する。このため、同じキーが左に `a` 行、右に `b` 行あれば、そのキーだけで `a × b` 組を出力する。

通常の `NULL` キーは索引に入れず、探索にも使わない。NULL 安全と指定されたキー要素だけは、専用の番兵値として符号化する。

### 6.2 入力の取り込みと構築側

メモリ内で処理する内部結合でも、最初に左右の入力を取り込み、実際のバイト数を測る。小さい側からハッシュ索引を構築し、大きい側で探索する。左側から索引を構築する場合も、出力列は常に `left + right` の順に並べる。出力位置には左行の位置を使う。

入力が大きい場合は、ハッシュ索引を複数の区画（shard）に分ける。探索側の行数が多く、複数のワーカーを利用できる場合は、探索範囲も帯状の区間（stripe）に分ける。各ワーカーの出力は最後に連結する。区間内の順序を保てる場合でも、SQL 結果全体の順序は保証しない。

### 6.3 小入力への適応

構築側が 1〜64 行で、スピルしていない内部結合では、キーの完全な集合を実行時フィルタとして作る。探索側もごく小さい間はハッシュ表を作らず、あらかじめ符号化した構築側キーを線形探索する。探索側が 4 行を超えた時点でハッシュ区画を構築し、残りの行をハッシュ探索へ切り替える。

この切り替えにより、小さな入力ではハッシュ表の構築費用を省ける。実測行数が予想より大きい場合は、線形探索を続けて `O(LR)` になることを避けられる。不一致だった探索行と、`NULL` キーを持つ探索行の数は診断情報へ記録する。

### 6.4 結合種別ごとの処理

内部結合は、ハッシュ索引の探索結果を一つずつ返せる。準結合、反結合、NULL 対応反結合、マーク結合、単一結合、外部結合では、入力全体の一致状態または未一致ビットマップが必要になる。そのため、種別ごとの処理で出力を実体化する。

- 準結合と反結合は、右側を存在集合として左行を判定し、左行と左位置だけを出力する。
- マーク結合は、一致する右行があれば `TRUE` を左行へ追加する。一致せず、右側に `NULL` キーがあれば `NULL`、それ以外は `FALSE` を追加する。左キーが `NULL` の場合は、右側が空なら `FALSE`、非空なら `NULL` になる。
- 単一結合は右を構築側とし、0 件なら右を `NULL` 補完、1 件なら連結、2 件以上なら失敗する。
- 左・右・完全外部結合は、一致済み状態を追跡し、保存側の不一致行を `NULL` 補完する。

外部結合、単一結合、マーク結合の出力位置には、左側を保存する行と一致行では左位置を使い、未一致の右保存行では右位置を使う。

物理計画の表示に残余条件が付く場合でも、`HashJoin` のハッシュ照合が処理するのは等値キーだけである。残余条件は、上位の Selection または残余述語を評価する別の結合方式で適用する。

### 6.5 実行中のスピル切り替え

メモリ内で処理を始めた場合でも、作業メモリの軟限界を超えると、取り込み中の入力を 16 個のハッシュ区画へ分けてスピルする。

- 一方だけがスピルした場合は、メモリに残る側から索引を作り、スピルした側を区画順に読み出して探索する。
- 両側がスピルした場合は、同じハッシュ規則で作った対応区画を読み、区画内で小さい側から索引を作って並列に結合する。
- 準結合、反結合、マーク結合、単一結合、外部結合では、必要な区画をすべて読み直し、区画間の一致状態を統合する。

I/O または復号に失敗すると、最初のエラーを保持し、部分出力を完全な結果として返さない。

### 6.6 ハイブリッドハッシュ結合

ハイブリッドモードでは、初めから 32 区画に分ける。右入力の区画 0 は、予算内に収まればメモリに残し、ほかの区画をスピルする。左入力の区画 0 は、メモリ内の右区画と直ちに照合する。残りの区画は対応するファイルへ書き、最後に左右の区画対を読み戻して結合する。

右側の区画 0 も予算に収まらない場合は、その区画もスピルし、通常の区画結合へ切り替える。現在のハイブリッド専用処理が扱うのは内部結合だけである。ほかの結合種別には、それぞれの意味を実装した専用処理を使う。

## 7. `SharedBuildParallelHashJoin`

`SharedBuildParallelHashJoin` は、右入力を全件読み、複数のワーカーで一つの並行ハッシュ表へ挿入する。表は 64 個の区画を持ち、区画ごとのミューテックスで挿入と探索を保護する。全ワーカーが構築を終えるまで同期した後、左入力も全件保持して範囲に分け、複数のワーカーで探索する。

各キーはバイト列へ変換し、FNV-1a でハッシュする。通常の SQL 等値では、`NULL` キーを右側のハッシュ表へ入れず、左側の `NULL` キーも不一致として扱う。右側に `NULL` キーがあったことは、NULL 対応反結合のために別途記録する。

対応種別は、内部結合、準結合、反結合、NULL 対応反結合、左外部結合である。右外部結合、完全外部結合、マーク結合、単一結合はこの実装では選ばない。

出力はワーカーごとのベクトルへ貯め、ワーカー番号順に連結する。完全なブロッキング演算で、共有ハッシュ表と出力の概算量をメモリへ計上する。内部結合と左外部結合の一致行、準結合と反結合の行には左位置を付ける。

共有表を使うと、構築側のデータを一つだけ保持すればよい。ただし、同じ区画への挿入と探索が集中するとミューテックスの競合が増える。ワーカーごとに独立した表を作る方式は複製が増える一方、区画のロック競合を避けられる。

## 8. `MergeJoin`

`MergeJoin` は左右が同じ複合キーで昇順に整列済みであることを要求する。キー列は空でなく、左右で同じ個数でなければならない。

両カーソルのキーを比較し、キーが小さい側を進める。キーが等しいときは、左右それぞれで同じキーが続く範囲（run）の末尾を求め、二つの範囲の直積を作る。残余述語があれば、各候補対に適用する。通常の `NULL` キーは一致しない。

対応種別は、内部結合、左・右・完全外部結合、準結合、反結合である。

- 準結合と反結合は、各左行について、同値範囲内に残余述語まで満たす相手があるかを調べ、左行を最大 1 回返す。
- 外部結合は、残余述語を満たした対だけを一致済みとする。キーが等しくても、すべての候補対が残余述語を満たさなければ、その行を `NULL` で補完する。
- 左右の同値範囲がそれぞれ `a` 行と `b` 行なら、候補比較は `a × b` 回になる。

整列済み入力に対する計算量は `O(L + R + 候補対)` である。ただし、この実装は左右の入力を全件保持してから結果を作るため、入力と出力の両方にメモリを使うブロッキング方式である。準結合と反結合では左の `RowPosition` を保存する。それ以外の逐次マージ出力には、有効な位置を付けない。

左右を読み切った直後に、子の状態を自身へ記録する。子が失敗していても、その時点までに保持した行を使ってマージ処理を続けるため、部分的な出力が残る場合がある。一方、演算子の状態は失敗のままである。返された行の有無だけでは、結果が完全かどうかを判断できない。

事前整列が必要なら総費用に `O(L log L + R log R)` が加わる。

## 9. `ParallelMergeJoin`

`ParallelMergeJoin` も、整列済みの左右入力を全件保持する。左入力をほぼ同じ大きさの範囲へ分けるが、同じキーが続く範囲の途中では分割しない。各左境界に対応する最初の右キー位置を二分探索で求め、左右の対応範囲を一つのワーカーへ割り当てる。

各ワーカーは逐次版と同じく、内部結合、準結合、反結合、左・右・完全外部結合と残余述語を処理する。複数のワーカーが同時に残余式のエラーを検出した場合は、ミューテックスで保護した状態に最初のエラーだけを記録する。

各区画の出力を区画番号順に連結するため、入力のキー範囲順を保つ。同値範囲を分割しないため、重複する組の欠落と、複数ワーカーによる二重処理を避けられる。

入力全体と全出力を保持するパイプラインブレーカーである。結合行と左側を保存する行には左位置を付け、未一致の右保存行には右位置を付ける。ワーカーの起動と同期に費用がかかるため、小さい入力では逐次版を使う。自動選択の主な対象は、残余述語のない大きな内部結合である。

## 10. `ApplyExecutor`

`ApplyExecutor` は、外側の一行を式の評価範囲に設定し、その行を参照する内側問い合わせを実行する。相関副問い合わせを通常の結合へ非相関化（decorrelate）できない場合に使う。

相関する `inner_query` がある場合は、外側行ごとに内側問い合わせを評価し、結果を一時的な行列へ保持する。相関しない `inner_exec` が与えられた場合は、最初の外側行を処理するときに一度だけ全件を読み、それ以降は保存した結果を再利用する。

内側各行と外側行を連結し、任意の述語を評価する。

- 準結合は最初の一致で外側行を返し、残りの内側行を見ない。
- 反結合は一致が見つかれば外側行を捨て、一致なしなら返す。
- 左外部結合は一致行をすべて返し、一致なしなら内側幅を `NULL` 補完する。
- その他は一致した連結行を返す。

結合種別に応じた専用処理があるのは、準結合、反結合、左外部結合だけである。それ以外の種別を指定すると、一致した対を返す内部結合相当の処理になる。したがって、右外部結合、完全外部結合、マーク結合、単一結合、NULL 対応反結合の意味をこの演算子では実現できない。

出力には外側行の位置を付ける。外側入力はストリーミングで処理するが、各外側行に対する内側の結果は実体化する。相関実行の費用は、おおむね `Σ inner_cost(outer_i)` である。非相関化、索引利用、相関キーごとの結果保存を利用できない場合は、外側行ごとに内側の処理を繰り返すため費用が大きくなる。

相関問い合わせの実行失敗と述語の評価失敗は、最初のエラーとして状態に記録する。一方、外側の実行器と非相関 `inner_exec` については、末尾まで読んだ後に子の状態を確認しない。非相関の内側入力が途中で失敗した場合も、それまでに得た行を保存済みの結果として再利用する。この経路へ渡す子の成功は、上位の境界で保証する必要がある。

## 11. `AsOfJoin`

`AsOfJoin` は、任意の等値キー群で右行を区画に分け、時刻条件を満たす右行のうち最も近い一行を選ぶ。

比較条件が `right_time <= left_time` なら、条件を満たす右時刻の最大値を選ぶ。`right_time >= left_time` なら、右時刻の最小値を選ぶ。最大遡及範囲（lookback）が指定されている場合は、時刻差がその範囲内にある候補だけを残す。

等値キーまたは時刻が `NULL` の行は一致しない。左外部モードなら右を `NULL` 補完し、内部結合相当モードなら捨てる。同じ最良時刻が複数ある場合は、候補列で最初に現れた行が残る。

右側の区画は時刻順に整列せず、候補を先頭から線形に調べる。そのため、計算量は `O(R + Σ bucket_size(left_i))`、最悪の場合は `O(LR)` になる。左右の入力を読み終えてから全出力を作るブロッキング方式であり、合成した行には有効な物理行位置を付けない。

左右の子が停止した理由は調べず、子の状態を自身へ転送しない。入力で障害が起きた場合は、その時点までに取得した行だけで作った結果を、正常な全結果と誤認する可能性がある。

## 12. `IntervalJoin`

`IntervalJoin` は、任意の等値キー群が一致し、さらに次の両端を含む区間条件を満たす右行をすべて返す。

```text
left_value + lower_offset <= right_value
right_value <= left_value + upper_offset
```

右入力を等値キーで区画に分け、各左行に対応する区画を先頭から調べる。等値キーまたは区間値が `NULL` の場合は一致しない。左外部モードでは、一致する右行がない左行に、右側の列数だけ `NULL` を付ける。

AS OF 結合と異なり、最も近い一行だけでなく、区間内の全候補を出力する。計算量は `O(R + Σ bucket_size(left_i) + 出力)`、最悪の場合は `O(LR)` である。全出力を実体化し、行位置は無効にする。

この演算子も、左右の子の状態を確認しない。入力が途中で失敗した場合、保持済みの部分入力から作った結果と、正常に全入力を処理した結果を区別できない。

## 13. 方式の選択指針

| 条件 | 有力な方式 |
|---|---|
| 任意述語、小入力 | 入れ子ループ結合 |
| 右に適切な索引、左が小さい | 索引結合 |
| 大きな等値結合、順序不要 | ハッシュ結合 |
| 作業メモリに収まらない等値結合 | ハイブリッドまたは区画化ハッシュ結合 |
| 両入力が既に同じキー順 | マージ結合 |
| 大きな整列済み入力 | 並列マージ結合 |
| 非相関化できない相関 | Apply |
| 直近の時系列対応 | AS OF 結合 |
| 時間帯・数値帯の全一致 | 区間結合 |

推定行数だけでなく、行幅、キー重複、`NULL` 率、残余述語の選択度、既存順序、出力行数を含めて選ぶ。同じキーが大量重複する場合、どの方式でも最終出力の直積費用そのものは避けられない。
