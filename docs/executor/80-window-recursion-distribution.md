# ウィンドウ・再帰・交換

ウィンドウ関数、再帰 CTE、`Exchange` は、子から受け取った一行をそのまま一行へ変換する処理ではない。ウィンドウ関数は同じパーティションの行、再帰 CTE は直前の反復で得た差分、`Exchange` は各行の配置先を必要とする。そのため、これらの演算子は関係またはパーティションを実体化する。

## 1. `WindowExecutor`

`WindowExecutor` は入力行を減らさず、各行の末尾にウィンドウ関数の結果列を追加する。最初の呼び出しで子を末尾まで読み、各ウィンドウ関数を順に計算する。すべての計算に成功した後で行を返す、完全なブロッキング演算子である。

パーティション内では行を整列するが、計算値は元の行番号に対応する位置へ書き戻す。そのため、最終出力の行順は子の入力順と同じである。入力の `RowPosition` は保存せず、出力位置は無効になる。

### 1.1 パーティションとウィンドウ順序

各入力行について `PARTITION BY` の式を評価し、同じキーを持つパーティションへ入れる。`NULL` 同士とすべての `NaN` は同値として扱う。パーティションを探すときは既存のキー列を線形探索するため、パーティション数を `G` とすると、構築の計算量は最悪 `O(NG)` になる。

各パーティションでは `ORDER BY` キーを評価し、安定ソートする。既定では、`NULL` を昇順の先頭、降順の末尾に置く。通常のウィンドウ順序では、`NaN` をすべての有限値と無限大より大きいものとし、すべての `NaN` を一つの同順位グループにまとめる。`COLLATE` を指定した文字列キーは、比較用に小文字化した内部キーを使う。

すべての整列キーが等しい行を、同順位行（peer）と呼ぶ。安定ソートによって入力順を保つため、同順位行の間では元の入力順になる。ただし、この順序は SQL が保証するものではない。結果に必要なら、行を区別できる整列キーを追加する必要がある。

`WindowExecutor` は、出力するウィンドウ関数ごとにパーティションと整列用の配置を作り直す。複数の関数が同じ `PARTITION BY` と `ORDER BY` を使う場合も、現在の処理では配置を共有しない。したがって、`W` 個の関数には、おおむね `W` 回分の整列費用がかかる。

### 1.2 フレームの既定値

フレームを明示しない場合は、次の範囲を使う。

- ウィンドウ順序がない場合: パーティション全体。
- ウィンドウ順序がある場合: `RANGE BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW`。現在行だけでなく、同じ整列キーを持つ同順位グループの末尾までを含む。

フレームは、整列済みパーティション上の閉区間 `[lo, hi]` として求める。開始位置が終了位置より後なら空のフレームとなり、`COUNT` は 0、ほかの集約は `NULL` を返す。

### 1.3 `ROWS`、`GROUPS`、`RANGE`

`ROWS` は、現在行の物理的な位置にオフセットを加減して境界を求める。オフセットは、`NULL` ではない非負の整数定数でなければならない。境界がパーティションの外に出る場合は、先頭または末尾に収める。

`GROUPS` は、行数ではなく同順位グループ数で前後の境界を求める。ウィンドウ順序が必要であり、オフセットには非負の数値定数を指定する。倍精度値も受け付けるが、`size_t` へ変換するときに小数部を切り捨てる。同じ整列キーを持つ一群を一単位として、開始グループと終了グループを決める。

`RANGE` のオフセット境界は、整列キーの値から求める。オフセットを使う場合は、整列キーが一つだけで、数値であることを前提とする。昇順と降順では加減する向きを反転する。整数キーは 64 ビットの端に近い場合も倍精度へ丸めず、拡張精度で境界を計算する。`NULL` キーは、同じ `NULL` を持つ同順位グループとして扱う。

オフセット自体の型と非負性は検査するが、整列キーが数値型かどうかはこの処理では検査しない。非数値キーをオフセット付きの `RANGE` に渡すと、数値変換の結果が `NaN` になる。その場合は型エラーを返さず、境界候補が見つからないときの代替処理または空フレームになる可能性がある。

三方式とも、`UNBOUNDED PRECEDING`、`offset PRECEDING`、`CURRENT ROW`、`offset FOLLOWING`、`UNBOUNDED FOLLOWING` を扱う。不正な型、負のオフセット、必要な整列キーの欠如は実行エラーになる。

### 1.4 フレームからの除外

フレームを求めた後、次の `EXCLUDE` を適用する。

| 指定 | 除外する行 |
|---|---|
| `NO OTHERS` | なし |
| `CURRENT ROW` | 現在行だけ |
| `GROUP` | 現在行と同じ同順位グループ全体 |
| `TIES` | 現在行自身を残し、ほかの同順位行を除く |

ウィンドウ順序がない場合は、全行を一つの同順位グループとみなす。除外を適用した後、集約の `WHERE` / `FILTER` を評価し、真になった行だけを集約へ渡す。

このフィルタ式の評価に失敗した場合、現在の実装はエラーを伝えず、結果を `NULL` とみなして行を除外する。そのため、フィルタ内の演算エラーが単なる不採用に変わる可能性がある。

### 1.5 順位関数

| 関数 | 計算 |
|---|---|
| `ROW_NUMBER` | パーティション内の 1 から始まる位置 |
| `RANK` | 同順位グループの先頭位置。次の順位までに同順位行数だけ間が空く |
| `DENSE_RANK` | 同順位グループの 1 から始まる番号。順位間の空きはない |
| `PERCENT_RANK` | `(RANK - 1) / (パーティション行数 - 1)`。1 行だけなら分母を 1 とする |
| `CUME_DIST` | 現在の同順位グループの末尾位置 / パーティション行数 |
| `NTILE(n)` | 先頭側の区画から一行ずつ余りを配り、区画の大きさの差を最大 1 にする |

`NTILE` の区画数は、`NULL` ではない正の整数でなければならない。行数より区画数が多い場合は、行が入る先頭側の区画番号だけが結果に現れる。

### 1.6 行参照関数

`LAG(value, offset, default)` と `LEAD` は、整列済みパーティション上で前後の行を直接参照する。オフセットの既定値は 1 であり、指定する場合は `NULL` ではない非負整数でなければならない。参照位置が範囲外なら、指定された既定値を返し、既定値がなければ `NULL` を返す。これらの関数はフレームではなく、パーティション内の位置を使う。

`FIRST_VALUE`、`LAST_VALUE`、`NTH_VALUE` は、計算済みのフレームと除外指定を使う。`NTH_VALUE` の `n` は、除外後の行列における 1 から始まる位置であり、正の整数でなければならない。対応する行がなければ `NULL` を返す。

`IGNORE NULLS` / `RESPECT NULLS` の指定は式に保存される。しかし、現在の位置参照処理は `NULL` を飛ばさず、指定位置の値をそのまま返す。この指定を実際の処理に反映するのは、後述するパーセンタイル関数の `RESPECT NULLS` だけである。

### 1.7 フレーム集約

順位関数と位置参照関数以外は、現在行ごとにフレーム内の除外されていない行を列挙して集約する。次の関数を扱う。

- `COUNT`、`COUNTIF`、`SUM`、`AVG`、`MIN`、`MAX`、`ANY_VALUE`
- `LOGICAL_AND`、`LOGICAL_OR`、`BIT_AND`、`BIT_OR`、`BIT_XOR`
- `ARRAY_AGG`、`STRING_AGG`、`ARRAY_CONCAT_AGG`
- `VAR_POP`、`VAR_SAMP`、`VARIANCE`、`STDDEV_POP`、`STDDEV_SAMP`、`STDDEV`
- `COVAR_POP`、`COVAR_SAMP`、`CORR`
- `APPROX_COUNT_DISTINCT`、`APPROX_QUANTILES`、`APPROX_TOP_COUNT`、`APPROX_TOP_SUM`
- `PERCENTILE_CONT`、`PERCENTILE_DISC`
- `ELEMENTWISE_SUM`、`ELEMENTWISE_AVG`

`DISTINCT` は、フレーム内の値を保存した配列を線形探索して重複を除く。`NULL` 同士とすべての `NaN` は同じ値として扱う。ハッシュ集合を使わないため、大きなフレームでは最悪で二乗時間になる。

整数 `SUM` はオーバーフローを検査し、`AVG` は倍精度浮動小数点数を返す。二引数の統計関数は、両方の引数が非 `NULL` である行だけを使う。`APPROX_*` も値を保存し、正確に整列または計数する。集約内 `LIMIT` は、`ARRAY_AGG` と `STRING_AGG` に対して、フレーム順の値へ適用する。一方、集約内 `ORDER BY` の指定は保存されるだけで、この処理では参照しない。

多くの関数は、フレーム内の値から `NULL` を先に除く。この処理により、スカラー集約とは次の違いが生じる。

- `ARRAY_AGG` は `NULL` 要素を保持せず、全要素が `NULL` なら `NULL` を返す。
- `APPROX_TOP_COUNT` と `APPROX_TOP_SUM` は `NULL` 値を候補に含めない。
- `ARRAY_CONCAT_AGG` は非配列値を失敗にせず飛ばし、有効配列がなくても型なし空配列を返す。
- `STRING_AGG` の区切りはフレームの各行で上書きされ、最後に残った行の値を使う。最後の値が `NULL` なら、既定値の `,` へ戻る。
- `MIN` は `NaN` を通常値より大きいものとして選ばず、`MAX` は `NaN` を選ぶ。スカラー `MIN` / `MAX` の「一つでも `NaN` があれば `NaN`」という規則とは異なる。
- 倍精度 `SUM` と配列要素の整数和は、オーバーフローを検査しない。

ウィンドウ版の `APPROX_TOP_SUM` は、`NULL` の重みを 1 として加算し、負値と `NaN` も拒否しない。この関数の結果でも、JSON のフィールド名には `count` を使う。一方、配列要素型の表示ではフィールド名を `sum` と宣言する。同点の順序には安定ソートを使わない。

ウィンドウ版の `APPROX_QUANTILES` は、個数が正かどうかだけを確認する。100000 という上限と引数型を十分に検査せず、値を直接比較して整列する。

ウィンドウ版の `COVAR_POP` では、引数の組を集める共通処理が 2 組未満を空入力として扱う。そのため、有効な組が一つの場合は 0 ではなく `NULL` になる。統計関数と要素別集約は、入力が数値または配列であることを前提とし、異なる型の値が来ても一部を明示的なエラーにしない。

`PERCENTILE_CONT` と `PERCENTILE_DISC` は、指定されたフレームを使わず、常にパーティション全体を参照する。既定では `NULL` を除外する。`RESPECT NULLS` を指定すると、`NULL`、`NaN`、通常値の順に並べるパーセンタイル専用の整列を行う。`PERCENTILE_DISC` は上側の離散順位を選び、`PERCENTILE_CONT` は隣接値を線形補間する。

各出力行についてフレーム全体を走査し直し、直前の行で計算した状態を差分更新しない。フレームがパーティション全体なら、一関数当たり最悪 `O(N²)` 回の集約更新に、パーティションの整列費用が加わる。入力行、計算済みの結果列、一時的な配置をすべてメモリに保持し、スピルは行わない。

### 1.8 失敗と再試行状態

子を読み切る途中で失敗した場合は、行を返さない。複数のウィンドウ列を計算する途中で失敗した場合は、追加済みの列数を記録する。再び呼び出されたときは、同じ列を二重に追加しない。ただし、すべての列の計算に成功するまで `computed` にはならず、一部の列だけを追加した行は出力しない。

## 2. `RecursiveCteExecutor`

`RecursiveCteExecutor` は、再帰 CTE を固定点反復で評価する。得られた関係を保持し、その後に要求駆動型で一行ずつ返す。結果は新しく作った関係の行なので、物理位置は無効である。

### 2.1 アンカーと差分

再帰本体を、初期結果を作るアンカーと、前回の結果から次の結果を作る再帰枝に分ける。

```text
result = anchor
delta  = anchor

while delta is not empty:
    bind CTE name = delta
    next = every recursive branch evaluated against that binding
    result += next
    delta = next
```

アンカーは `UNION` の再帰枝を外し、本体全体の `ORDER BY`、`LIMIT`、`OFFSET` も外して一度だけ評価する。各反復で CTE 名に結び付けるのは、累積結果 `result` ではなく直前の差分 `delta` だけである。この方式を準単純評価（semi-naive evaluation）と呼ぶ。同じ行の導出を過去の全結果から毎回やり直さず、直前に増えた行だけをワークテーブルとして使う。

各 `Relation` は問い合わせのメモリ予算を使い、必要に応じて一時ファイルへスピルする。反復を始める前に差分を独立した関係として実体化するため、再帰枝は直前の反復で確定したスナップショットを読む。

### 2.2 `UNION ALL` と重複除去

`UNION ALL` は、導出したすべての行を次の差分と累積結果へ追加する。停止条件がなければ、同じ行を繰り返し生成する可能性がある。

重複除去版は、深さ列を付ける前の本体行を、既出行を保存した `seen` 配列と線形比較する。アンカーとすべての反復を通して、すでに現れた行を捨てる。`NULL` 同士、すべての `NaN`、`-0.0` と `+0.0` は、それぞれ同値として扱う。ハッシュ集合を使わないため、結果行数を `M` とすると、重複検査は最悪 `O(M²)` になる。

`UNION BY NAME` は、再帰枝の列をアンカーの出力列名に対応付ける。再帰枝にない列は `NULL` で補い、余分な列は出力しない。通常の `UNION` は列位置で対応付ける。

### 2.3 深さ指定と停止条件

深さ列を要求した場合は、アンカーに 0、最初の再帰結果に 1、その後は反復番号を付ける。`lower` より浅い行は最終出力に含めないが、次の差分には残す。このため、浅い行からさらに深い行を導出できる。`upper` を超える反復は開始しない。

反復は次のいずれかで停止する。

- 差分が空になる。
- 深さの上限を超える。
- 1024 回の固定上限に達する。
- 次の差分を加えると累積結果が 10000000 行を超える。この場合は失敗する。

反復が 1024 回の上限に達しても、エラーにはせず、その時点までの結果を返す。そのため、停止しない `UNION ALL` 再帰では、完全な固定点ではなく、安全上限までの先頭部分を結果とする場合がある。再帰枝が一つもない本体は、通常の問い合わせとして一度だけ実行する。

行数上限の判定には、深さが `lower` 以上で最終出力に入った累積結果と、次の差分の行数を足した値を使う。`lower` 未満の導出行は `seen` と差分には残るが、この累積値には含まれない。また、アンカーだけで上限を超え、再帰を直ちに終了する場合も、アンカーの行数だけを検査する処理はない。したがって、10000000 は導出した全行に対する厳密な上限ではない。

初期化済みフラグは、固定点計算を始める前に立つ。固定点計算または最終 `Relation` の読み出しに失敗すると、そのエラーを状態に保持し、同じ計算を自動的にはやり直さない。最終結果を配列へコピーする途中で失敗した場合は、それまでにコピーした行が内部に残る。失敗後に再び呼び出すと、その部分行が見える可能性がある。失敗した実行器は継続して使わず、問い合わせ単位で破棄する必要がある。

## 3. `ExchangeExecutor`

`Exchange` は、行を複数の区画チャネルへ振り分ける。並列結合、分散集約、ワーカー間のデータ移動に使う境界である。ここでの実装はネットワーク上で逐次転送する方式ではなく、子の全行をプロセス内の区画別配列へ格納するパイプラインブレーカーである。

行と `RowPosition` の組を保持するため、各区画の読み手は元の位置を取得できる。最初の実体化要求だけをミューテックスで保護して実行し、完了フラグはアトミック変数で公開する。子が途中で失敗した場合は、最初のエラーを `Exchange` の状態へ伝える。

### 3.1 配置方式

| 方式 | 行き先 |
|---|---|
| `Hash` | 指定キー列を `NULL` も区別できるバイト列に変換し、FNV-1a の `hash % P` で区画を選ぶ |
| `Range` | 第一キーを `P - 1` 個の上限境界と比較し、最初に `key < bound` となる区画へ入れる。`NULL` は区画 0 |
| `Broadcast` | 全 `P` 区画へ同じ行を複製する |
| `Gather` | 全行を区画 0 へ集める |

ハッシュキーでは、各列の前に `NULL` または非 `NULL` を表すタグを付ける。そのため、`NULL` を持つ同じキーは同じハッシュ区画に入る。指定した列位置が行幅の外にある場合は、その列をキーに加えない。

非 `NULL` 値は現在の物理表現をそのまま符号化する。グループキーで行う、内部表現の異なる `NaN` の統一や、`-0.0` から `+0.0` への変換は行わない。そのため、SQL 上は同値であるキーが、異なるハッシュ区画に入る可能性がある。

`Range` 方式は第一キーだけを使う。`P > 1` の場合は、境界が正確に `P - 1` 個あることを構築時に検査する。`P = 1` では検査を省くが、呼び出し側が渡せる境界は 0 個のままである。複数の境界を渡すと、比較結果によっては存在しない区画番号を返す。

第一キーの列位置が行幅内にあることも、呼び出し側が保証する。`Hash` 方式と異なり、範囲外の列位置を無視する処理はない。値と比較できない境界は飛ばし、どの境界よりも前に来なければ最後の区画へ入れる。区画内では入力順を保つ。境界自体が値の全順序に従って並んでいることも、呼び出し側が保証する。

`Broadcast` 方式の格納量は `O(PN)`、ほかの方式は `O(N)` である。スピルは行わない。メモリ使用量の計算では入力行を一度しか数えないため、`Broadcast` 方式が実際に保持する複製分を計上できない。

子の停止後にエラーを状態へ記録しても、それまでに各区画へ入れた行は破棄しない。直接読み出すカーソルと区画ビューは、保持済みの行を先に返し、それぞれが末尾に達した時点で失敗を返す。そのため、状態が失敗である区画の行を完全な結果として扱うことはできない。

### 3.2 全区画を読むカーソル

`ExchangeExecutor::Next` を直接呼ぶと、区画 0 から `P - 1` までを順に連結して返す。`Hash` と `Range` 方式では元の全体入力順を失い、区画内の順序だけを保つ。`Broadcast` 方式では各区画の複製をすべて連結するため、各入力行が `P` 回現れる。`Gather` 方式では区画 0 だけに行が入る。

このカーソルは単一の消費側だけが使う。複数のスレッドが同じ `Next` を同時に呼ぶための同期処理はない。バッチ読み出しも同じカーソルを使い、指定件数まで行を追加する。

## 4. `PartitionScanExecutor`

`PartitionScanExecutor` は、`Exchange` が内部的に返す実行器ビューである。一つの区画だけを先頭から読む。各ビューは独立した読み出し位置を持つため、ワーカーごとに異なる区画を読む用途に使える。

最初のビューが読み始めた時点で `Exchange` が未実体化なら、共有 `Exchange` の実体化を開始する。ビューは `Exchange` を共有所有するため、元の `Exchange` オブジェクトが外側の計画から外れた後も、ビューが存在する間はデータが残る。末尾では `Exchange` が保持するエラーを転送し、失敗を正常な末尾として扱わない。

区画別の配列自体は変更されない。ただし、同じ区画に対して二つのビューを作ると、どちらのビューも全行を読む。行をワーカー間で一度ずつ動的に割り当てる作業キューではない。

## 5. `RemoteScan`

`RemoteScan` は、遠隔処理または別の実行段階から届くバッチを受け取る。`Exchange` が生産側で区画を作るのに対し、`RemoteScan` は消費側のチャネル境界になる。保持済みのバッチ列を読む方式と、スレッド安全なキューで到着を待つ方式がある。

チャネルが閉じられ、キューも空になると、正常な末尾を表す。独立したエラー状態はないため、生産側または通信処理の失敗は外側のプロトコルで扱う。詳しい読み出し手順は[遠隔入力](30-scan-source.md#12-remotescan遠隔入力)に示す。

## 6. `RelationalExecutor`

`RelationalExecutor` は、文単位で関係を評価する処理を `Next` インターフェースへ接続する互換境界である。最初の `Next` で問い合わせ全体を実行し、最終 `Relation` の全行を `rows_` 配列へコピーする。その後、配列から一行ずつ返す。

関係評価処理は、入力の構築、フィルタ、結合、ウィンドウ、グループ化、射影、重複除去、整列、制限、副問い合わせ、CTE を、一つの実行時状態の上で処理する。中間 `Relation` はメモリを予約し、軟限界を超えると一時ファイルへスピルできる。ただし、最後に全出力を実行器自身の配列へコピーするため、この境界はストリーミングではない。結果行数に比例するメモリが必要になる。

実行時状態には、次の情報も含まれる。

- 同じ基底関係を複数回使う場合の再利用キャッシュ
- 相関・非相関副問い合わせの結果、ハッシュ、索引のキャッシュ
- 走査、フィルタ、結合、射影、整列、集約の処理時間と件数
- ハッシュ結合の方式、比較数、中間行数の最大値、スピル回数
- 実行時フィルタ、短絡評価、反結合の診断値

実行または一時ファイルの読み書きに失敗すると、そのエラーを `GetStatus` へ伝える。返す行は関係演算で新しく作った結果なので、位置は無効である。`Dump` は未実行の実行器を動かさず、実行済みの場合だけ、実体化した行数と収集済みの統計を表示する。`Explain` は文から推定した物理計画を表示するだけで、問い合わせを実行しない。

初期化済みフラグは、全工程が成功した後にだけ立つ。そのため、失敗後に再び呼び出すと、問い合わせ全体を再実行する。一方、基底クラスの状態には最初のエラーが残る。後の試行に成功して行を返しても、実行器全体は失敗状態のままである。失敗後の再利用を回復処理として使うことはできない。

## 7. `GroupedFinishExecutor`

`GroupedFinishExecutor` は、最適化済みの `FROM`、結合、`WHERE` からなる中核計画と、文全体を扱う関係評価処理をつなぐ内部境界である。

最初の呼び出しで、中核計画から物理実行器の木を作り、全行を `Relation` へ実体化する。中核計画は、`WHERE`、走査フィルタ、結合条件、残余述語をすでに適用している。そのため、後段では `WHERE` を再評価しない。実体化した後、次の処理を行う。

1. グループキーごとの集約状態の構築、またはスカラー集約
2. 集約結果を参照する `HAVING`
3. 選択リストの最終射影
4. グループ化前の列や選択リストの別名も参照できる `ORDER BY`
5. `DISTINCT` / `DISTINCT ON`
6. `OFFSET`、`LIMIT`、`WITH TIES`

グループキーでは、すべての `NaN` と正負のゼロを、それぞれ同じ SQL 値として扱う。各グループの代表行と集約結果の表を式の評価範囲に設定するため、`HAVING` や射影内の相関副問い合わせからも参照できる。単純な型付き集約には、状態を直接更新する高速処理を使う。それ以外は共通集約器で処理する。

中核計画の入力と後段処理の結果はどちらも実体化し、最後に全結果を配列へ保存する。中間 `Relation` はスピルできるが、実行器自身は最終出力を全件保持する。出力位置は無効である。中核計画、式評価、一時ファイルのいずれかで失敗すると、行を返す前にエラーを伝える。実行統計は、この境界が所有する実行時状態に記録する。

初回の初期化に成功したかどうかにかかわらず、初期化済みフラグを立てる。そのため、後段処理が失敗しても自動的には再試行しない。最終 `Relation` から配列へコピーする途中で失敗した場合は、コピー済みの部分行が残る。再び呼び出すとその行が見える可能性があるが、状態は失敗のままである。失敗後に同じ実行器を読み続けることはできない。

`RelationalExecutor` と `GroupedFinishExecutor` は、多数の物理演算を内部で選ぶ関係評価の境界である。計画上の独立した走査や結合を置き換えるものではない。要求駆動型の実行器木と、文全体の意味を処理する関係評価を接続する。
