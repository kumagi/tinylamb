# 集約

集約は複数の入力行から中間状態を作り、最後に結果値へ変換する。グループなしの集約は入力全体を一つのグループとみなし、必ず 1 行を返す。`GROUP BY` はキーごとに 1 行を返す。多くの集約は入力をすべて読むまで結果が確定しないため、パイプラインブレーカーになる。

## 1. 集約の三段階

集約処理は、次の三段階からなる。

1. **入力**: 引数式と `FILTER` を評価し、`NULL` や `DISTINCT` を処理する。
2. **蓄積**: 行数、合計、極値、集合、配列など、関数ごとの状態を更新する。
3. **最終化**: `AVG = SUM / COUNT` のように状態から SQL 値を作る。

状態を二つ併合できる集約は、入力を区画ごとに処理してから部分状態をまとめられる。`COUNT`、`SUM`、`MIN`、`MAX` は典型例である。入力順そのものを必要とする `ARRAY_AGG(... ORDER BY ...)` や、グループ全体を見てから対象行を選ぶ `HAVING MAX/MIN` は、そのままでは単純な部分併合ができない。

### 1.1 共通の入力修飾

一般の集約器は次の修飾を同じ順序で扱う。

- `WHERE`/`FILTER` が真でない行を除く。`FALSE` と `NULL` はどちらも不採用である。
- `HAVING MAX condition` または `HAVING MIN condition` があれば、条件値のグループ極値を求め、その極値と等しい行だけを残す。条件が `NULL` の行は候補にならない。
- 集約内 `ORDER BY` があれば安定整列する。既定の `NULL` 配置は昇順で先頭、降順で末尾である。
- 集約内 `LIMIT` があれば整列後の先頭だけを残す。
- `DISTINCT` があれば同じ引数値を一度だけ蓄積する。全 `NaN` は一つの値に正規化され、`-0.0` と `+0.0` も同値である。

`HAVING MAX/MIN`、集約内の順序・制限、多引数関数などは行を一時保存してから上記の順序で再生する。単純な関数は行到着時に状態を更新できる。

集約内 `ORDER BY` の比較器は、一つのキーが同値だった場合に次のキーへ進まず、その時点で二行を同順位と判定する。このため複数の整列キーを指定しても、先頭のキーが同じ行では後続のキーを使って順序を決めない。整列キーが一つだけなら、この制約は結果に影響しない。

### 1.2 `NULL` と空入力

原則として集約引数の `NULL` は無視する。例外は `ARRAY_AGG` が `NULL` 要素を保持することと、`APPROX_TOP_COUNT`/`APPROX_TOP_SUM` が `NULL` 自体を集計対象の値として扱うことである。

空入力に対するグループなし集約も 1 行を返す。`COUNT`、`COUNTIF`、`APPROX_COUNT_DISTINCT` は 0、`HLL_COUNT.MERGE` も 0、通常の `SUM`、`AVG`、極値、配列・文字列・統計関数は `NULL` になる。グループキーがある場合、空入力にはグループがないため 0 行である。ただし、空のグルーピング集合、すなわち総計は例外として 1 行を作る。

## 2. 集約関数の状態と意味

### 2.1 基本関数

| 関数 | 保持する状態 | 最終値と注意点 |
|---|---|---|
| `COUNT(*)` | 入力行数 | `NULL` を含むすべての行を数える |
| `COUNT(expr)` | 非 `NULL` 数 | 空なら 0 |
| `COUNTIF(expr)` | 真と評価される非 `NULL` 値の数 | 空なら 0 |
| `SUM` | 整数合計または倍精度合計と件数 | 非 `NULL` がなければ `NULL`。符号付き・符号なし整数のオーバーフローは失敗。有限な倍精度入力だけから無限大になった場合もオーバーフロー |
| `AVG` | 倍精度合計と件数 | 件数 0 なら `NULL`。整数も倍精度へ変換して平均する |
| `MIN` / `MAX` | 現在の極値と `NaN` フラグ | 非 `NULL` がなければ `NULL`。一つでも `NaN` があれば結果は `NaN` |
| `LOGICAL_AND` / `LOGICAL_OR` | 非 `NULL` 真理値の積・和 | 全値が `NULL` なら `NULL`。空集合を真とはみなさない |
| `BIT_AND` / `BIT_OR` / `BIT_XOR` | 整数値に対するビット演算の累積結果 | 非 `NULL` がなければ `NULL`。符号なし属性を保存する |
| `ANY_VALUE` | 最初の非 `NULL` 値 | 選択を決定的にするため到着順の最初を保持する |

### 2.2 配列と文字列

`ARRAY_AGG` は入力値を配列へ追加する。通常の集約と違って `NULL` 要素も保存し、`DISTINCT` では複数の `NULL` を一要素へ畳む。宣言型から配列要素型を保存するため、全要素が `NULL` でも可能な限り元の要素型を失わない。入力が 0 件なら空配列ではなく `NULL` である。

`STRING_AGG` は非 `NULL` 値を区切り文字で連結する。区切り文字を省略した場合は `,`、指定式が `NULL` なら失敗する。集約内 `ORDER BY` と `LIMIT` は連結前に適用される。値が一つもなければ `NULL` である。

区切り式は、フィルタや制限を適用した後に残った最初の行で一度だけ評価し、その値を採用する。それ以降の行で異なる区切り値が得られても、結果には反映しない。最初の行の区切りが `NULL` なら失敗する。一度区切りを採用した後に現れる `NULL` は検査しない。

`ARRAY_CONCAT_AGG` は各非 `NULL` 配列の要素列を順に連結する。入力値が配列でなければ失敗し、非 `NULL` 配列がなければ `NULL` を返す。

`ELEMENTWISE_SUM` と `ELEMENTWISE_AVG` は配列を添字ごとに集約する。入力配列の長さが異なる場合、結果長は観測した最大長になる。各位置の `NULL` は無視し、その位置に値が一つもなければ結果要素を `NULL` にする。全入力配列が `NULL` なら結果全体が `NULL` である。

整数要素の和は 64 ビットの格納先へ直接加算し、スカラー `SUM` のようなオーバーフロー検査を行わない。合計が 64 ビット整数の範囲を超える配列では、スカラー集約と同じエラーにならない。

### 2.3 統計関数

分散・標準偏差・共分散・相関は丸め誤差を抑えるため、内部で拡張精度の和を保持する。

| 関数 | 有効行 | 分母・結果条件 |
|---|---|---|
| `VAR_POP`, `STDDEV_POP` | 引数が非 `NULL` | `n`。`n = 0` は `NULL` |
| `VAR_SAMP`, `STDDEV_SAMP` | 引数が非 `NULL` | `n - 1`。`n < 2` は `NULL` |
| `COVAR_POP` | 両引数が非 `NULL` | `n`。`n = 0` は `NULL` |
| `COVAR_SAMP` | 両引数が非 `NULL` | `n - 1`。`n < 2` は `NULL` |
| `CORR` | 両引数が非 `NULL` | 共分散偏差を両変数の偏差積平方根で割る。`n < 2` は `NULL` |

二引数関数は片方だけが `NULL` の行も丸ごと除外する。相関で片方の分散が 0 の場合など、浮動小数点演算自体が定義しない結果は IEEE 754 の結果に従う。

### 2.4 分位点、上位値、異なる値の概数

`APPROX_QUANTILES(value, number)` は非 `NULL` 値を保持して整列し、0 から `number` までの `number + 1` 個の代表値を選ぶ。`number` は正で 100000 以下でなければならない。名前に反して、この実行経路は入力全体を保存して厳密に整列するため、メモリは `O(N)`、時間は `O(N log N)` である。

この整列は生の値比較を使うため、`NaN` と通常値を全順序化しない。`NaN` を含む分位列の位置は `PERCENTILE_CONT` の明示的な NaN-first 規則とは一致せず、信頼できない。また `number` が倍精度で渡された場合は整数へ切り捨てて使う。

`PERCENTILE_CONT(value, p)` は `0 <= p <= 1` を要求し、非 `NULL` 数値を整列して隣接値を線形補間する。`NaN` は他の値より前にまとめる。入力が空なら `NULL` である。

`APPROX_TOP_COUNT(value, k)` は、`NULL` を含む各値の出現回数を正確に数え、回数の多い順に最大 `k` 件を返す。同数なら、最初に現れた順を保つ。

`APPROX_TOP_SUM(value, weight, k)` は、値ごとに非負の重みを合計する。重みが `NULL` なら加算せず、負値または `NaN` なら失敗する。すべての重みが `NULL` である値も候補として保持し、合計を `NULL` として末尾側に置く。

どちらの関数も、`k` は正で 100000 以下でなければならない。名称に `APPROX` とあるが、この処理は値ごとの正確な表を保持する。

`APPROX_COUNT_DISTINCT` は、非 `NULL` 値をハッシュ集合へ入れる。現在の処理は正確な集合サイズを返すため誤差はないが、異なる値の数に比例するメモリを使う。

### 2.5 HLL/KLL 状態

次の関数は、部分実行の間で受け渡せる直列化済み状態を入出力する。

- `HLL_COUNT.INIT` は値を HLL 系状態へ追加し、バイト列の状態を返す。
- `HLL_COUNT.MERGE_PARTIAL` は複数の状態を併合し、再びバイト列の状態を返す。
- `HLL_COUNT.MERGE` は併合後に異なる値の数を取り出す。
- `KLL_QUANTILES.INIT_INT64`、`INIT_UINT64`、`INIT_DOUBLE` は型別の KLL 系状態を作る。
- `KLL_QUANTILES.MERGE_PARTIAL` は同じ型の状態を併合し、バイト列を返す。

状態には種類と精度を記録する。種類が異なる状態や、形式が不正な状態を併合すると失敗する。精度が異なる状態は拒否せず、大きい方の精度値を採用する。`INIT` の精度引数が `NULL` である行を一度でも取り込むと、最終状態全体が `NULL` になる。

現在の状態表現は、値を直列化した列を保持する。HLL の併合は値を正確に重複除去し、KLL は値の多重集合を保持して整列する。そのため、固定サイズの確率的スケッチを使う一般的な実装よりも多くのメモリを使う。

## 3. `AggregationExecutor`

`AggregationExecutor` は、グループキーを持たないスカラー集約を実行する。最初の `Next` で子を末尾まで読み、集約値を並べた 1 行を返す。2 回目以降の呼び出しでは行を返さない。出力は特定の入力行に対応しないため、物理行位置は無効である。

処理経路は三つある。

1. `COUNT(*)`、整数・倍精度列の直接参照、畳み込み可能な数値定数だけからなる基本集約は、`DataChunk` の型付き列を直接読む。
2. それ以外の式、`DISTINCT`、フィルタ、順序付き集約、拡張集約は、行単位の共通集約器を使う。
3. 単一の符号付き `INT64` 列に対する単純な `SUM` は、大きな入力でオーバーフロー検査付きの JIT カーネルを利用できる。既定では、累積 20000000 行に達した後にコンパイルを試み、`NULL` のないバッチだけをカーネルへ渡す。

型付き処理を選ぶ判定では、`DISTINCT`、`WHERE` / `FILTER`、集約内 `ORDER BY` の有無だけを確認する。`HAVING MAX/MIN` と集約内 `LIMIT` は確認しない。JIT `SUM` の判定も同じである。このため、`HAVING MAX/MIN` または集約内 `LIMIT` が付いた基本集約を高速処理へ割り当てると、その修飾を適用しない。

共通集約器を使う場合でも、このスカラー実行器は `HAVING MAX/MIN` の条件式を `AggregateInput.condition` に設定しない。共通集約器からは、すべての行の条件値が `NULL` に見える。その結果、全行が除外され、空入力に対する最終値を返す。集約内 `ORDER BY` と `LIMIT` は、共通集約器で処理する。`HAVING MAX/MIN` を含む集約は、条件値を正しく設定するグループ集約の実行境界へ割り当てる必要がある。

数値定数を型付きで更新する処理が明示的に対応するのは、`COUNT`、`SUM`、`AVG`、`MIN`、`MAX` である。数値定数を引数とする `BIT_AND` / `BIT_OR` / `BIT_XOR` と `LOGICAL_AND` / `LOGICAL_OR` も、型付き処理の対象と判定される。しかし、すべての集約を型付きのまま処理できるバッチでは、定数用の分岐が状態を更新しないため、結果は `NULL` のままになる。

ほかの汎用集約が同じバッチに含まれ、バッチ全体が行単位処理へ切り替わった場合は、行用の分岐がこれらの定数を更新する。同じ演算でも、列を直接参照する引数は列用の分岐で処理される。

汎用処理では、子が停止した後に子の状態を自身へコピーする。ただし、子が失敗した場合も、それまでの集約状態から 1 行を組み立てる。そのため、行が返ったことだけでは成功を判断できない。式評価と最終化のエラーは、最初のものを状態に保持する。

JIT `SUM` は、バッチの取得行数が 0 になった後に子の状態を確認せず、それまでの合計を返す。そのため、下位の失敗による部分合計と、正常に末尾まで読んだ合計を区別できない。JIT 処理へ接続する子の成功は、外側の境界で保証する必要がある。

計画に `HashAggregation`、`SortAggregation`、`StreamAggregation` と表示されていても、グループなしの場合は同じスカラー集約器を使う。表示名だけでは、ハッシュ表の利用や入力順の利用を判断できない。

## 4. `ParallelAggregationExecutor`

`ParallelAggregationExecutor` も、グループなしで 1 行だけを返す。推定入力が 8192 行以上の場合に選択候補となる。ワーカー数は、実行環境が同時に動かせるスレッド数と 16 の小さい方であり、最低 1 とする。

各ワーカーは独立した部分状態を持つ。子の `NextBatch` 呼び出しだけをミューテックスで直列化し、取得したバッチの列走査は並列に行う。全ワーカーの終了後、ワーカー番号順に部分状態を併合して最終化する。併合順を固定しているため、バッチの割り当てが同じなら結果を再現しやすい。ただし、浮動小数点の加算順は逐次実行と異なる場合がある。

列を直接参照する型付き処理が実際に蓄積するのは、`COUNT`、`SUM`、`AVG`、`MIN`、`MAX` である。分散、標準偏差、共分散、相関には、専用の拡張精度状態を使う。

フィルタまたは `DISTINCT` がある場合は、行単位の汎用処理へ切り替える。ワーカーごとの重複除去用集合を併合時に値として再入力するため、複数のワーカーに現れた重複も一度だけ数える。汎用処理は、これらに加えて `LOGICAL_AND` と `LOGICAL_OR` を扱う。

一方、入力規模だけで並列方式を選ぶ側は、集約関数の種類を制限しない。そのため、列を直接参照する論理集約は型付き処理に分類されても、対応する分岐がないので結果が `NULL` になる。`COUNTIF`、ビット集約、配列、文字列、上位値、スケッチ、パーセンタイルなどの拡張集約も、汎用処理の既定分岐では状態を更新しない。`HAVING MAX/MIN`、集約内 `ORDER BY` / `LIMIT`、区切り式など、グループ全体の情報を使う修飾も評価しない。これらの集約を並列方式へ割り当てることはできない。

二引数統計関数に `DISTINCT` が付いている場合は、ワーカー数を 1 に減らす。ただし、重複判定には引数の組ではなく先頭引数だけを使う。同じ先頭値と異なる第二引数を持つ行を区別できないため、逐次版と同じ結果になるとは限らない。倍精度 `SUM` の型付き処理には、有限値だけを加算して無限大になった場合のオーバーフロー検査もない。

最初のワーカーが失敗すると停止フラグを立てる。すべてのスレッドの終了後、そのエラーを演算子の状態に保持する。次の `Next` で空入力に対する集約結果を返すことはない。

## 5. `PartialAggregate` と `FinalizeAggregate`

二段集約は、局所入力から中間状態を作る `PartialAggregate` と、それらをキーごとに併合する `FinalizeAggregate` に分かれる。どちらも全入力を読み切ってから結果を列挙する。

`PartialAggregateExecutor` と `FinalizeAggregateExecutor` は、それぞれ上記二クラスの公開別名である。別の状態形式や実行方式を持たない。

`PartialAggregate` はグループキーを評価し、正規化したキーをハッシュ表へ入れる。内部表現の異なる `NaN` は一つにまとめ、負のゼロは正のゼロに変換する。中間列は次の形である。

- `COUNT`: 部分件数の一列
- `SUM`: 部分合計の一列
- `AVG`: 部分合計と部分件数の二列
- `MIN` / `MAX`: 部分極値の一列
- `LOGICAL_AND` / `LOGICAL_OR`: 部分真理値の一列

`FinalizeAggregate` は、同じグループキーを持つ中間行をまとめる。件数と合計は加算し、極値と論理値は中間値を使って再び集約する。平均は最後に `全体の合計 / 全体の件数` として計算する。グループのないスカラー集約では、入力が空でも空の部分状態を 1 行作る。

この二段処理が正しく扱うのは、上記の関数だけである。ほかの関数は、既定処理によって中間状態を合計として扱ってしまうため、二段処理へ割り当てられない。`DISTINCT`、集約内の順序、複雑な多引数状態も対象外である。

`SUM` と `AVG` の中間スキーマには倍精度浮動小数点数を使う。そのため、単一集約器による整数の厳密な加算とは、精度とオーバーフローの性質が異なる。

`PartialAggregate` は、処理を始める時点で実体化済みフラグを立てる。子が失敗した場合は、そのエラーを呼び出し結果として返すだけで、自身の状態には保持しない。このため、最初の呼び出しが失敗した後でも、再び呼び出すと、失敗前までに作った部分行を読み出せる。`FinalizeAggregate` は子の状態を確認せず、部分状態のストリームが途中で止まっても、正常に末尾へ達したものとして最終化する。

## 6. `TwoPhaseDistinctAgg`

`TwoPhaseDistinctAgg` は、グループキーごとに異なる値の集合を作り、通常集約の状態も同時に保持する。すべての入力を処理した後、第二段階で状態を結果へ変換する。グループなし集約とグループ集約の両方を扱う。

`TwoPhaseDistinctAggExecutor` はこのクラスの公開別名であり、実行時の差はない。

`DISTINCT` 集約と通常集約のどちらも、`COUNT`、`SUM`、`AVG`、`MIN`、`MAX` の五種類を扱う。`WHERE` フィルタは、値を集合または集約状態へ加える前に適用する。グループキーと重複判定値では `NaN` と負のゼロを正規化するため、物理的なビット列が異なっていても同じ SQL 値として扱う。

入力をすべて読む完全なブロッキング方式であり、グループごとのハッシュ状態と重複除去用集合をメモリに保持する。スピルは行わない。ほかの集約関数を渡すと既定動作になり、正しい意味を実装しない。そのため、物理計画は対応する五種類だけを割り当てる必要がある。出力位置は無効である。

`SUM` は、`DISTINCT` の有無にかかわらず、最終スキーマに合わせて倍精度浮動小数点数へ変換される。`DISTINCT` 付きの `MIN` / `MAX` は、順序を持たない集合を浮動小数点の大小演算で集約する。そのため、`NaN` を含む場合の結果は集合の反復順に依存する。

実体化済みフラグは処理開始時に立て、末尾で得た子のエラーを自身の状態に保持しない。このため、子の失敗後に再び呼び出すと、部分結果が見える場合がある。

## 7. `GroupingSetsExecutor`

`GroupingSetsExecutor` は、まず子の全行を保存する。その後、指定されたグルーピング集合ごとに全行を走査して、独立に集約する。すべてのグループキー列を常に出力し、現在のグルーピング集合に含まれないキー列には `NULL` を設定する。

たとえばキー `(a, b)` に対する `ROLLUP` は `(a,b)`, `(a)`, `()` の順、`CUBE` は四つの部分集合を要素数の多い順に作る。空入力では空でないグルーピング集合は 0 行だが、`()` は総計を 1 行返す。この行の `COUNT` は 0、他の集約は `NULL` である。

通常および `DISTINCT` の `COUNT`、`SUM`、`AVG`、`MIN`、`MAX` と `ANY_VALUE` を扱う。`ANY_VALUE` は通常経路で最初の非 `NULL` 値、`DISTINCT` 経路では集合の代表値になる。その他の種類には既定の合計または件数処理があるだけなので、割り当て対象にしない。

グルーピング集合の数を `S` とすると、各集合について全入力を再走査するため、基本的な計算量は `O(SN)` となる。これにハッシュ集約の費用が加わる。入力全体と各グルーピング集合のグループ状態をメモリに保持し、スピルは行わない。出力はグルーピング集合の列挙順に並び、各集合の中ではグループの初出順になる。

`DISTINCT` 付きの `MIN` / `MAX` は、順序を持たない集合の反復順で浮動小数点の大小演算を行う。そのため、`NaN` があると結果が反復順に依存する。

子のエラーは実体化処理の戻り値には使うが、自身の状態には保持しない。また、処理開始時に実体化済みと記録する。このため、失敗を返した後に再び呼び出すと、失敗前までの入力で作ったグルーピング集合の結果を読み出せる。

## 8. `DistributedAggFinalize`

`DistributedAggFinalize` は、複数の部分集約ストリームを読む。グループキーを、バイト列の比較順と値の比較順が一致する memcomparable 形式に符号化し、一つのハッシュ表へまとめる。扱う状態は `COUNT`、`SUM`、`AVG`、`MIN`、`MAX` である。`AVG` の入力には、部分合計と部分件数の二列が必要になる。

すべての入力を読み切った後にグループごとの最終行を作るため、パイプラインブレーカーになる。グループ表には順序を持たないマップを使うので、後段で明示的に整列しない限り出力順は保証されない。出力行は特定の格納行に対応しないため、位置は無効である。

メモリ予算に計上するのは、完成行の配列要素数に固定要素幅を掛けた量だけである。グループキー、ハッシュ表、集約状態、行内の可変長値は含まれない。また、グループキーは値をそのまま memcomparable 形式へ符号化し、内部表現の異なる `NaN` や負のゼロをグループ用に正規化しない。そのため、SQL 上は同値であるキーが別のグループに分かれる可能性がある。

合計の状態は倍精度浮動小数点数で保持する。このため、大きな整数の精度と整数オーバーフローの性質は、単一の `AggregationExecutor` が使う整数処理とは異なる。複数ノードまたは複数区画から部分状態を渡す側は、列位置と中間表現をこの最終化器の指定に合わせる必要がある。

各入力の状態を確認しないため、途中で失敗した部分ストリームも、正常に末尾へ達したものとして最終化する。符号なし整数の部分合計も、符号付き整数のビット列として解釈してから倍精度へ変換する。`MIN` / `MAX` の `NaN` は特別扱いせず、浮動小数点の比較結果と到着順に従う。

## 9. `DictionaryBatchAggregation`

`DictionaryBatchAggregation` は要求駆動型の演算子ではなく、一つのグループ列と一つの集約列をバッチから処理する専用カーネルである。グループ値を初出順に連続番号 `0..G-1` へ変換し、その番号で直接参照できる集約状態の配列を更新する。グループキーの種類が少ない場合は、各行で大きなグループ表を探索せず、小さな連続配列を更新できる。

対応する関数は `COUNT(expr)`、`SUM`、`AVG`、`MIN`、`MAX` である。`COUNT` は集約列の `NULL` を数えないため、`COUNT(*)` とは異なる。合計と平均には倍精度の状態を使う。結果は `[グループ値, 集約値]` の二列であり、グループの初出順にバッチとして返す。

辞書にはハッシュマップと値配列を使い、集約状態には `O(G)` のメモリを使う。複数のグループ列、式引数、フィルタ、`DISTINCT`、スピル、行位置は扱わない。

どの関数を指定した場合も、内部の集約状態は件数、倍精度の合計、最小値、最大値を同時に更新する。そのため、集約列が数値であることが実質的な前提になる。整数の合計も倍精度へ変換し、オーバーフローは検査しない。`MIN` / `MAX` は `NaN` を特別扱いしないため、`NaN` が最初に現れるか後で現れるかによって結果が変わる場合がある。この補助カーネル自体はエラー状態を持たない。

## 10. 集約方式を選ぶ条件

集約方式は SQL の構文だけでは決まらない。集約状態を併合できるか、グループ数と異なる値の数がいくつか、入力がどれほど大きいか、順序指定があるか、どれだけのメモリを利用できるかによって決まる。

- 小さいスカラー集約には、スレッドの起動費用がかからない単一の集約器が適する。
- 大きいスカラー集約では、独立した部分状態を並列に作れる。ただし、浮動小数点結果の下位ビットは加算順に依存する場合がある。
- グループ集約では、すべての段階でグループキーの正規化規則を一致させる必要がある。
- `DISTINCT`、配列、上位値、分位点、スケッチ状態のメモリ量は、入力行数よりも異なる値の数または保存する値数に強く依存する。
- 二段集約と分散集約の中間スキーマは、通常の最終スキーマと異なる。特に `AVG` は一つの値ではなく、合計と件数の組として受け渡す。
- ここで説明したグループ集約の演算子には、一般的な外部ハッシュ集約が行う再分割スピルがない。入力規模またはグループ数の見積もりが小さすぎると、作業メモリが見積もり以上に増える。

集約後の `HAVING`、最終射影、`DISTINCT`、`ORDER BY`、`LIMIT` を関係単位で完了する境界については、[GroupedFinishExecutor](80-window-recursion-distribution.md#7-groupedfinishexecutor)で扱う。
