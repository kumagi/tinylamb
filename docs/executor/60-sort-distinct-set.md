# 整列・重複除去・集合演算

整列は、後続の演算子が利用できる順序を作る。重複除去と集合演算は、多重集合における各行の出現回数を変える。どの方式でも、値の全順序、`NULL`、`NaN`、型変換の規則を一致させる必要がある。規則が異なると、同じ SQL でも選ばれた物理方式によって結果が変わる。

## 1. 順序キーの規則

各整列キーには、次の指定がある。

- 評価する式
- 昇順または降順
- 明示的な `NULLS FIRST` / `NULLS LAST`、または既定値

既定は昇順で `NULLS FIRST`、降順で `NULLS LAST` である。複数キーは左から辞書式に比較し、先行キーが同値のときだけ次のキーを見る。

浮動小数点では、内部表現の異なるすべての `NaN` を一つの同値キーへ正規化し、`-0.0` と `+0.0` も同値にする。配列は要素の辞書式順序で比較する。符号なし整数は符号付き整数へ変換せず、本来の数値領域で比較する。

ただし、`NaN` と通常値の相対位置は、現在の三つの処理で一致していない。`SortExecutor` のバイト列符号化は、昇順で `NaN` を `+∞` より後ろに置く。共通の `CompareForOrderBy` を使う Top-N と `PdqSort` は、昇順で `NaN` をすべての非 `NULL` 通常値より前に置く。`PartialSortExecutor` と `MergeAppendExecutor` の一部は、浮動小数点の大小演算を直接使う。この比較では、`NaN` と任意の数値のどちらも他方より小さくない。このため、`NaN` を含む入力では、物理方式によって相対順が異なる。

## 2. `SortExecutor`

`SortExecutor` は入力全体を読み、指定したキーによる全体順序を作るパイプラインブレーカーである。行と `RowPosition` を対で保持するため、並べ替えた後も元の物理位置を保存する。

### 2.1 キー符号化

入力時にキー式を評価し、比較可能なバイト列へ符号化する。符号化には、型タグ、整数の符号変換、降順のための反転、`NULL` を表す番兵を含める。そのため、一般経路ではバイト列を比較するだけで複合キーの順序が決まる。

単一キーが `INT64` または `DATE` の列参照なら、順序を保つ 64 ビットキーへ変換し、基数ソート（radix sort）を使う。

- 符号付き整数は符号ビットを反転し、符号なし整数として比較した順序を数値順に合わせる。
- 符号なし整数はビット列をそのまま使う。
- 降順ではすべてのビットを反転する。
- `NULL` は別配列へ分け、指定位置の前または後へ置く。

一般の浮動小数点符号化では、`NaN` を一つの表現へ正規化し、昇順で `+∞` より後ろに置く。降順では符号化したバイト列を反転する。

### 2.2 メモリ内整列

入力が作業メモリに収まる場合、単一整数キーには基数ソート、一般キーには安定ソートを使う。入力が 4096 行以上あり、複数のワーカーを利用できる場合は、範囲ごとに並列で整列する。その後、隣接する整列済み列（run）を追加領域を抑えたマージで段階的に統合する。

計算量は一般に `O(N log N)` である。単一固定長キーの基数ソートはキー幅が一定なので、`O(N)` とみなせる。行、位置、キー、並べ替え順を表す配列を保持するため、メモリ使用量は `O(N)` である。

同じキーを持つ行は入力順を保つ。基数ソートの各段階、安定ソート、並列マージのいずれでも、この安定性を維持する。

### 2.3 外部整列

次の行を追加すると作業メモリの軟限界を超える場合は、現在保持している行を整列し、一つの整列済み列として一時ファイルへ書く。その後でメモリを解放し、次の整列済み列を作る。

全入力を処理した後、各整列済み列から最大 128 行を先読みする。各列の先頭キーを最小ヒープへ入れ、k 路マージ（k-way merge）する。同じキーでは番号の小さい列を先に選び、元の入力順に由来する安定性を保つ。行数ヘッダの不整合、復号、キーの再評価、I/O のいずれかに失敗すると、問い合わせ全体を失敗させる。

最後にマージした結果は、再びメモリ上の出力配列へ保存する。整列済み列を作る段階のピークメモリは抑えられるが、最終出力全体を保持するメモリは必要になる。したがって、結果を逐次返す外部マージではない。

## 3. `TopNExecutor`

`TopNExecutor` は `offset + limit` 番目までに必要な行だけを保持する。`WITH TIES` の有無でアルゴリズムが異なる。

### 3.1 `WITH TIES` なし

容量 `K = offset + limit` の最大ヒープを使う。各入力行のキーを一度評価し、ヒープに空きがあれば追加する。満杯の場合は、現在の最下位行より上位に来る行だけを置き換える。

全入力を処理した後、ヒープ内の上位 `K` 行を完全に整列し、先頭の `offset` 行を飛ばして返す。同じキーを持つ行は、入力時の連番で最終的な順序を決めるため、到着順を保つ。

```text
時間: O(N log K + K log K)
メモリ: O(K)
```

`offset + limit` が整数範囲を超える場合は最大値へ飽和させる。`limit = 0` は空結果であり、`LimitExecutor` の 0 = 無制限という内部表現とは異なる。

### 3.2 `WITH TIES`

境界キーと同じキーを持つ行数は、固定容量のヒープだけでは判断できない。そのため、全入力を保持して整列する。`offset` の後に `limit` 行を取った境界を求め、最後の行とすべての整列キーが等しい後続行を追加する。

この経路は `O(N log N)` 時間と `O(N)` メモリを使う。同順位行の判定には値の等値演算を使い、`NULL` 同士、全 `NaN`、`-0.0/+0.0` はそれぞれ同じキーとして扱う。

どちらの処理でも行位置を保存し、キー式の評価に失敗した場合は最初のエラーを保持する。

Top-N の浮動小数点比較には `CompareForOrderBy` を使う。`NULL` の位置は `NULLS FIRST` または `NULLS LAST` で決める。非 `NULL` 値は、昇順では `NaN`、通常値の順に並ぶ。この順序は、前節の `SortExecutor` における `NaN` の位置とは一致しない。

`limit = 0` の場合は、子を一行も読まず、直ちに空結果を確定する。

## 4. `PartialSortExecutor`

`PartialSortExecutor` は二つの動作モードを持つ。

### 4.1 固定ブロックモード

`block_size > 0` の場合は、入力をその行数ごとの独立したブロックへ分ける。各ブロックを完全に整列する。`top_k` がブロック幅より小さい場合は、先頭の `top_k` 行だけを部分整列して返す。

ブロック間では比較しないため、出力全体が整列キー順になるとは限らない。各ブロックがすでに上位キーの範囲ごとに分かれている場合や、ブロックごとの上位値だけが必要な場合に利用できる。このモードでは `offset` を適用しない。

### 4.2 全入力から上位 K 行を求めるモード

`block_size = 0` の場合は全入力を保持し、必要な範囲を `offset + top_k` とする。この範囲が入力行数より小さければ、`partial_sort` で先頭部分だけの順序を確定し、`offset` 以降の必要行を返す。`top_k = 0` の場合は全体を整列し、`offset` 以降をすべて返す。

どちらも、全出力をメモリへ保持するパイプラインブレーカーである。入力行と位置の概算量を作業メモリへ計上する。

比較式が失敗すると、最初のエラーを整列中に記録する。行 API は整列の完了後にそのエラーを返すが、バッチ API は記録済みのエラーを確認せず、保持している行を返す。また、全入力から上位 K 行を求めるモードで一行も得ないまま子が失敗すると、早期に処理を終えるため、子の状態を取り込まない。

比較では、浮動小数点の `<` を両方向に直接適用する。そのため、`NaN` は通常のすべての数値と同順位であるかのように扱われる。この比較は厳密弱順序を満たさないので、`NaN` を含む結果の位置は保証されない。`offset + top_k` の加算には飽和処理がなく、極端に大きな値では整数が回り込む可能性もある。

## 5. `IncrementalSortExecutor`

`IncrementalSortExecutor` は、入力が `prefix_keys` で整列済みであることを前提とする。隣接して同じ接頭キー値を持つ最大区間を見つけ、その区間だけを `suffix_keys` で整列する。

```text
入力: 接頭キー=A の区間 | 接頭キー=B の区間 | 接頭キー=C の区間
処理:    接尾キーで整列     接尾キーで整列     接尾キーで整列
```

接頭キーの区間順は変えない。したがって、入力が前提を満たしていれば、結果は `prefix_keys + suffix_keys` の全体順序になる。接頭キーの同値判定では `NULL` 同士とすべての `NaN` を同値として扱い、接尾キーの整列には `PdqSort` の順序を使う。

一つの接頭キー区間だけを保持すれば逐次処理できるアルゴリズムだが、現在の実装は入力全体を先に保持する。その後、各区間を切り出して整列し、全出力を保存する。このためパイプラインブレーカーとなり、メモリ使用量は `O(N)` である。各区間が小さい場合は比較回数が減るものの、保持量は減らない。

行 API は、子または比較式の失敗を返す。一方、バッチ API は保持済みの `sort_error` を確認せずに出力を返す。エラーを親へ伝える必要がある経路では、行 API と同じ状態確認を外側で行う必要がある。

## 6. `PdqSort`

`PdqSort` は要求駆動型の演算子ではなく、`Row` または `(Row, RowPosition)` の配列を整列キーで並べる補助カーネルである。名称とは異なり、現在の実装は `std::sort` を使う。

比較中に式エラーが起きても例外を送出せず、最初のエラーを外部の `Status` に記録する。その比較対は同値として扱い、整列処理自体は最後まで実行する。呼び出し側は、整列後に状態を確認する。

`NULL` の配置、昇順と降順、すべての `NaN` の同値化には、共通の `ORDER BY` 比較を使う。昇順では `NaN` を通常値より前に置く。

`IncrementalSortExecutor` が接尾キーの区間を整列するときなどに利用する。

## 7. `DistinctExecutor`

計画表示上の名称は `HashDistinct` だが、現在の `DistinctExecutor` はハッシュ表を使わない。既出行を保存した配列を線形探索する。

各入力行について、すべての列を既出行と比較する。初出ならその行を既出配列へ保存して直ちに返し、重複なら次の入力を読む。最初の非重複行から出力できるストリーミング方式である。ただし、非重複行が `D` 個ある場合の計算量は最悪 `O(ND)` であり、全行が異なれば `O(N²)` になる。メモリ使用量は `O(D)` である。

`DISTINCT ON` 式列が指定された場合は、行全体ではなく評価済みキー列を既出集合と比較し、各キーで最初に現れた入力行を返す。明示的な事前整列があれば、その順序における「最初」を選べる。

同値規則は次のとおりである。

- `NULL` 同士は重複とみなす。
- 全 `NaN` を同じ値とみなす。
- `-0.0` と `+0.0` を同じ値とみなす。
- 浮動小数点は許容誤差（epsilon）ではなく、正規化後の厳密な同値判定を使う。

最初に残った行の `RowPosition` と入力順を保存する。

## 8. `SortDistinctExecutor`

`SortDistinctExecutor` は直前に返した行一つだけを保持し、現在行が同値なら捨てる。時間 `O(N)`、追加メモリ `O(1)` である。

正しく全重複を除くには、同値な行が隣接するよう入力が行全体の同じ同値規則で整列済みでなければならない。この前提がなければ、離れた位置の重複は残る。

同じ値が連続する各区間の最初の行と位置を返し、入力順序をそのまま保つ。

## 9. `SetOperationExecutor`

`SetOperationExecutor` は同じ列数の複数入力を全件読み、共通型へ揃えた後に集合演算を行う。`UnionAllExecutor` はこのクラスの別名であり、別アルゴリズムではない。

### 9.1 型の統一

各列について全入力値から共通型を求める。

- 同型、または片側が `NULL` 型なら他方を使う。
- `INT64` と `DOUBLE` は `DOUBLE`。
- DATE と文字列は DATE を保ち、文字列を日付へ解析する。
- 文字列と数値・日付の組合せは、DATE の上記例外を除き文字列へ変換する。
- 互換規則がなければ失敗する。

集合同値では、型が統一された後に `NULL` 同士、全 `NaN`、等しい配列を同じ行とみなす。

### 9.2 出現回数

入力ごとのある行 `x` の出現回数を `c_i(x)` とする。

| 演算 | 出力回数 |
|---|---|
| `UNION ALL` | `Σ c_i(x)` |
| `UNION DISTINCT` | どこかにあれば 1 |
| `INTERSECT DISTINCT` | 全入力にあれば 1 |
| `INTERSECT ALL` | `min_i c_i(x)` |
| `EXCEPT DISTINCT` | 第 1 入力にあり、後続入力に一度もなければ 1 |
| `EXCEPT ALL` | `max(c_0(x) - Σ_{i>0} c_i(x), 0)` |

SQL は結果の列挙順を保証しない。メモリ内の処理では、第 1 入力の走査順に `INTERSECT` と `EXCEPT` の代表行を選ぶ。`UNION` では、全入力を通して最初に現れた行を代表にする。出力には、その代表行の `RowPosition` を付ける。

### 9.3 スピル

重複除去を伴う集合演算が作業メモリに収まらない場合は、各入力を 32 個のハッシュ区画へ分けてスピルする。全入力から共通型を確定した後、値をその型へ変換してから再びハッシュする。たとえば整数 `1` と倍精度 `1.0` が、型変換前の異なる区画に分かれたままになることを防げる。

対応区画をメモリへ読み、通常の集合演算を行って区画結果を連結する。スピル形式は行位置を保持しないため、この経路の出力位置は無効になる。

`UNION ALL` は重複集合を必要としないためスピル切替の対象外だが、現在の実装は全入力をメモリへ保持してから連結する。論理的にはストリーム化可能でも、物理的にはブロッキングである。

## 10. `MergeAppendExecutor`

`MergeAppendExecutor` は、同じ整列キーで整列済みの複数入力を、重複を残したまま一つの整列ストリームへ併合する。各入力から先頭行を一つずつ保持する。キーが最小の先頭行を返した後、その行が属していた入力から次の行を読み出す。

入力する実行器の数と入力スキーマの数は一致していなければならず、不一致なら実行に失敗する。また、構築時に少なくとも一つの入力が必要である。入力が 0 個だと、すべての先頭行が空であることを処理する分岐が、存在しない最初の入力の状態を参照してしまう。空集合は別の演算子で表す必要がある。

同じキーなら、入力番号の小さい行を先に選ぶ。`NULL` の配置と昇順・降順は整列キーの指定に従う。出力スキーマが `DOUBLE` で入力が `INT64` の場合は、倍精度浮動小数点数へ変換する。それ以外の互換性のないキー型・列型、および行幅の不一致はエラーになる。

入力数を `S` とすると、現在の実装は各出力行について、すべての入力の先頭行を線形に調べる。そのため、計算量は `O(NS)`、保持メモリは `O(S)` である。二分ヒープを使う一般的な k 路マージの `O(N log S)` とは異なる。各行の元の `RowPosition` は保存する。

浮動小数点の先頭キーは、`CompareForOrderBy` ではなく、等値演算と大小演算で直接比較する。`NaN` 同士は等しいが、`NaN` と通常値のどちらも相手より小さくない。そのため両者を同順位として扱い、入力番号で順序を決める。したがって、`NaN` を含む入力では、各入力が個別に整列済みであっても、全体を正しい数値順に併合できない。

`UNION ALL` と組み合わせると、枝ごとの既存順序を利用し、全件を再整列せず多重集合を順序付きで連結できる。
